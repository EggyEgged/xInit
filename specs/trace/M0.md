## Notes on how clauses are tested
- State-machine model (rule 6): `api_model.rs`. No proptest dependency exists (adding one needs approval), so 24 fixed xorshift seeds × 8 steps drive Signal/Wait/Stop/Pid against a reference model written from B-M0-029 to B-M0-031. Failures print the seed and trace.
- B-M0-018 / B-M0-031 commands get a readiness echo into a FIFO (`trap '' TERM; echo ready > "$1"; exec /usr/bin/sleep 60`). The spec's command can log `running` (after exec of /bin/sh) before the trap is installed. A SIGTERM in that window kills sh and makes the test flaky. The FIFO replaces any sleep or poll.
- Children-of-self checks (B-M0-016, B-M0-032) hold an exclusive lock that every child-creating test takes shared, so parallel tests cannot add children meanwhile.
- Output is collected with a test-owned end marker written into the pipes after xrginit's exit has been observed (rule 11). No test waits for pipe EOF.

## Untested
- **B-M0-026 privileged success path** (uid, gid and groups switched to the target user; requires root). Not written. The spec requires it to fail without root, and the unprivileged EPERM case must fail as root (as root, setgroups/setgid/setuid succeed). With both tests present, one of them fails in every environment and the gate can never pass. See Spec disputes.
- **B-M0-021, blocked-mask part** ("whatever mask ... xrginit itself has"): only inherited *ignored* dispositions are exercised. Rust's `Command` resets the signal mask in the child, so a test cannot start xrginit with a blocked mask without extra FFI in a pre_exec hook. That is possible, but it was left out to keep the suite simple. Coverage is partial.
- **Exit code 5 / `event=internal-error`**: the spec says no M0 test can provoke it.
- **SIGHUP behaviour**: the spec says no test asserts it either way.
- **B-M0-028 "each line is written as soon as its event happens"**: covered only indirectly. Tests wait for `running` and `stop` lines while xrginit is still running. No test asserts per-line timing.
- **B-M0-016 / B-M0-025 / B-M0-026 `state=failed` keys after a start failure**: whether `pid` appears (a fork happened, exec did not) is ambiguous. Only `state=failed`, ERROR and the absence of `code`/`signal` are asserted.
- **`key=` on `unit-invalid` for `schema-version` and `unsupported-service-type`**: those variants carry no key. The spec says `key` appears "for key errors" without listing which kinds those are, so it is not asserted.
- **`signal()` between death and reap** (model state Dying): unspecified. The model accepts `Ok(())` or `Err(Os{errno:3})` and never `Exited`.
- **`stop()` on an already reaped or dying Service**: unspecified, never generated.

## Spec disputes (for the orchestrator)
1. B-M0-026: "privileged success path, requires root; without root it must fail" conflicts with the unprivileged EPERM test, which needs a non-root user. One of the two is red in every environment.
2. B-M0-027 vs the Rust runtime: a std `main` installs SIGSEGV and SIGBUS handlers (seen in the self-check fake as SigCgt 0x440), and B-M0-027 forbids them. Not a test defect. The implementer has to reset them, or the spec has to allow them.
3. B-M0-018 command race (see Notes): the tests add a readiness echo. The spec could add it to its own example.
